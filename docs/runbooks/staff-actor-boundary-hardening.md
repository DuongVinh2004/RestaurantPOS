# Staff Actor Boundary Hardening

Batch 06 is an inventory pass only. It does not change runtime behavior.

Search method:

- `rg` was unavailable in this Windows app runtime, so the inventory used PowerShell `Get-ChildItem ... | Select-String`.
- Scope was `app/Modules/**/*.php`.
- Patterns covered nullable staff actor inputs such as `?int $staffUserId`, `?int $staffActorUserId`, `?int $actorUserId`, nullable actor context parameters, and null guards such as `if ($staffUserId === null)`.

Classification:

- A: Staff-only HTTP use case. It should fail closed when the staff actor is missing.
- B: System/background use case. It should use an explicit system actor or system context instead of relying on `null`.
- C: Public/customer/read-only use case. `null` may be valid, but the path must not expose staff-only data or skip staff authorization when used from staff routes.

## Implementation Order

1. Foundation: add fail-closed staff actor APIs on or beside `StaffBranchContextService`, plus explicit system/fallback branch-scope APIs. Do not remove existing nullable methods until callers are migrated.
2. Money first: harden `OrderSettlementWorkflow`, `StaffCashierShiftService`, invoice, reconciliation, deposit/refund/capture services. These combine branch scope, cashier shift state, money movement, and audit.
3. Order and KDS: harden staff order reads, table order mutation, item lifecycle, dispatch, and ticket actions. Preserve row-version and realtime side effects.
4. Floor and service sessions: harden table release/move/assignment/check-in/walk-in session methods. Preserve Batch 05 branch-denial-before-business-state ordering.
5. Inventory/procurement/reporting/conversation reads: separate staff HTTP reads from system jobs and public/customer paths.
6. Mixed public/customer paths: replace nullable actor ids with explicit customer, staff, or system context objects where routes share workflows.

## Notes For Later Batches

- Do not blanket-change every nullable actor parameter. Some `null` values currently represent customer/public or background/system workflows.
- Tests should prove both missing actor fail-closed behavior and same-branch authorized response compatibility.
- Any method that currently loads sensitive relations before branch scope should be fixed together with actor hardening.
- Existing route contracts should stay stable unless a later batch explicitly changes them.
