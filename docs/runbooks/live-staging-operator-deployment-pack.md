# Live Staging Operator Deployment Pack

This guide provides the exact steps, configurations, and verification commands required to deploy RestaurantPOS to a real Ubuntu 22.04 or 24.04 server for Staging Cutover.

> [!WARNING]
> This runbook is intended for a real Ubuntu VPS. Executing these commands blindly in a non-Ubuntu environment (like Windows or Mac) will fail. Destructive commands (like database drops/restores) will be explicitly marked.

---

## 1. Preconditions

Before proceeding, ensure you have:
- **Server**: A fresh Ubuntu 22.04 or 24.04 VPS/EC2 instance.
- **Access**: `sudo` access via SSH.
- **Network**: DNS A record pointing to the server's public IP (e.g., `staging.restaurantpos.com`).
- **Target Architecture**: PHP 8.2+, Node.js LTS (20+), MySQL 8+, Redis, Nginx (or Caddy), Supervisor.

---

## 2. Package Installation Commands

Run the following commands on your Ubuntu server to install the required stack:

```bash
# Update packages
sudo apt update && sudo apt upgrade -y

# Install PHP and extensions
sudo apt install -y software-properties-common
sudo add-apt-repository ppa:ondrej/php -y
sudo apt update
sudo apt install -y php8.2-fpm php8.2-mysql php8.2-redis php8.2-mbstring php8.2-xml php8.2-bcmath php8.2-curl php8.2-zip unzip curl git supervisor nginx certbot python3-certbot-nginx mysql-server redis-server

# Install Composer
curl -sS https://getcomposer.org/installer | php
sudo mv composer.phar /usr/local/bin/composer

# Install Node.js LTS
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt-get install -y nodejs
```

## 3. Directory Layout

We recommend the following layout for atomic deployments (or simple clone deployments):

```text
/var/www/restaurantpos
├── current -> /var/www/restaurantpos/releases/20260601120000
├── releases
│   ├── 20260601120000
│   └── 20260602153000
└── shared
    ├── .env
    └── storage
```
For a simple clone deployment, you may just use `/var/www/restaurantpos` as the root.

## 4. Deployment Options

### Option A: Clone Repository directly (Simpler)
```bash
cd /var/www
sudo git clone https://github.com/DuongVinh2004/RestaurantPOS.git restaurantpos
cd restaurantpos
sudo chown -R www-data:www-data storage bootstrap/cache
sudo chmod -R ug+rw storage bootstrap/cache
```

### Option B: Deploy Immutable Artifact
Extract the `.tar.gz` artifact generated by CI into `/var/www/restaurantpos/releases/[timestamp]` and symlink it to `current`.
Ensure storage is symlinked to the `shared/storage` directory.

## 5. Environment File Template

Copy the `docs/runbooks/templates/staging.env.template` to `/var/www/restaurantpos/.env` and inject your real credentials.

**Required Keys**:
- `APP_ENV=staging`, `APP_DEBUG=false`, `APP_KEY`
- `DB_CONNECTION`, `DB_HOST`, `DB_DATABASE`, `DB_USERNAME`, `DB_PASSWORD`
- `REDIS_HOST`, `REDIS_PORT`, `REDIS_PASSWORD` (if configured)
- `SENTRY_LARAVEL_DSN`
- `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_DEFAULT_REGION`, `BACKUP_S3_BUCKET`

> [!IMPORTANT]
> **NEVER** use placeholders like `changeme` or `example` for secrets. The `booking:launch-readiness` gate will scan the `.env` file and **FAIL** the deployment if dummy secrets are detected.

## 6. SQL-first Bootstrap

Because RestaurantPOS is a SQL-first project, **DO NOT** use `php artisan migrate` to initialize the database.

> [!CAUTION]
> The bootstrap command will drop existing tables if run destructively. In staging, only run this for initial setup.

```bash
cd /var/www/restaurantpos
composer install --no-dev --optimize-autoloader
php artisan key:generate

# Bootstrap the SQL-first schema
composer bootstrap:booking

# Verify schema integrity
php artisan booking:deploy-check --mode=preflight --strict --json
```

## 7. Supervisor Queue Config

Create the file `/etc/supervisor/conf.d/restaurantpos-queue.conf`:

```ini
[program:restaurantpos-queue]
process_name=%(program_name)s_%(process_num)02d
command=php /var/www/restaurantpos/artisan queue:work --sleep=3 --tries=3 --timeout=90
autostart=true
autorestart=true
stopasgroup=true
killasgroup=true
user=www-data
numprocs=1
redirect_stderr=true
stdout_logfile=/var/www/restaurantpos/storage/logs/queue-worker.log
stopwaitsecs=3600
```

---

## 8. Supervisor Scheduler Config

Create the file `/etc/supervisor/conf.d/restaurantpos-scheduler.conf`:

```ini
[program:restaurantpos-scheduler]
command=php /var/www/restaurantpos/artisan schedule:work
autostart=true
autorestart=true
stopasgroup=true
killasgroup=true
user=www-data
redirect_stderr=true
stdout_logfile=/var/www/restaurantpos/storage/logs/scheduler-worker.log
```

Apply the Supervisor changes:
```bash
sudo supervisorctl reread
sudo supervisorctl update
sudo supervisorctl restart restaurantpos-queue:*
sudo supervisorctl restart restaurantpos-scheduler
sudo supervisorctl status
```
*Verify both are listed as RUNNING.*

---

## 9. Nginx Config

Create `/etc/nginx/sites-available/restaurantpos-staging`:

```nginx
server {
    listen 80;
    server_name staging.restaurantpos.com;
    root /var/www/restaurantpos/public;

    add_header X-Frame-Options "SAMEORIGIN";
    add_header X-Content-Type-Options "nosniff";

    index index.php;

    charset utf-8;

    location / {
        try_files $uri $uri/ /index.php?$query_string;
    }

    location = /favicon.ico { access_log off; log_not_found off; }
    location = /robots.txt  { access_log off; log_not_found off; }

    error_page 404 /index.php;

    location ~ \.php$ {
        fastcgi_pass unix:/var/run/php/php8.2-fpm.sock;
        fastcgi_param SCRIPT_FILENAME $realpath_root$fastcgi_script_name;
        include fastcgi_params;
    }

    location ~ /\.(?!well-known).* {
        deny all;
    }
}
```

Enable it:
```bash
sudo ln -s /etc/nginx/sites-available/restaurantpos-staging /etc/nginx/sites-enabled/
sudo nginx -t
sudo systemctl reload nginx
```

## 12. Verification Commands

Run these to verify the deployment is healthy:

```bash
cd /var/www/restaurantpos
composer validate
composer audit
vendor/bin/pint --test
vendor/bin/phpstan analyse --memory-limit=1G --no-progress
php artisan test

# System Health
php artisan booking:doctor --json

# Deploy Check
php artisan booking:deploy-check --mode=preflight --strict --json

# Manifest Check
php artisan booking:release-manifest --json

# Final Launch Readiness Gate
php artisan booking:launch-readiness --target=staging --json
```

Verify Daemons and Logs:
```bash
sudo supervisorctl status
redis-cli ping
mysql -u root -p -e "SELECT VERSION();"
tail -n 100 storage/logs/laravel.log
```

## 13. Evidence Collection

All `.json` reports generated by the health and readiness commands are automatically stored in:
`storage/app/booking_release/staging_rehearsal_evidence/` (or default artifact dirs).

> [!WARNING]
> Do NOT store `.env` files or raw secrets in the evidence collection.

---

## 14. Rollback

If you need to rollback due to a critical error:
1. Revert code: Symlink `/var/www/restaurantpos/current` to the previous release folder.
2. Restore DB: Import the pre-deploy MySQL dump.
3. Supervisor: Restart queue and scheduler (`sudo supervisorctl restart all`).
4. Cache: Run `php artisan optimize:clear`.
5. Verify: Re-run `php artisan booking:launch-readiness`.

---

## 15. Troubleshooting

- **Scheduler heartbeat stale**: Check if `restaurantpos-scheduler` is running in `supervisorctl status`. Ensure no permissions issues in `storage/logs/laravel.log`.
- **Launch Readiness fails on placeholder secrets**: Verify `.env` does not contain any strings like `changeme`, `dummy`, `example`.
- **MySQL access denied**: Check `DB_USERNAME` and `DB_PASSWORD` in `.env`.
- **CORS block**: Ensure `CORS_ALLOWED_ORIGINS` in `.env` precisely matches the frontend URLs.
