# Booking backup and restore runbook

## Goal

Produce a repeatable, evidence-backed backup and restore rehearsal flow for the booking backend before release cutover and during recovery drills.

For the canonical DR drill pack, use:

- `php artisan booking:dr-drill --mode=metadata-verify --json`
- `php artisan booking:dr-drill --mode=dry-restore --target-db=<scratch_db> --json`
- `php artisan booking:dr-drill --mode=full-isolated-restore --target-db=<scratch_db> --drop-target-first --json`

Detailed mode matrix and operator steps:

- `docs/runbooks/booking-disaster-recovery-drill.md`

## Backup

1. Export a fresh logical backup with:
   - `tools/mysql/backup_release.sh --json`
2. Confirm `manifest.json` and `checksums.sha256` exist.
3. Confirm `latest-manifest.json` points to the intended backup set.
4. Archive the manifest JSON together with the release evidence generated by CI.

## Restore rehearsal

Use a scratch database, not the live application database.

```bash
export RESTORE_DB_DATABASE="${DB_DATABASE}_restore_rehearsal"
./tools/mysql/restore_release.sh --drop-target-first --json
```

Expected verification steps:

- backup manifest integrity check
- recreate scratch database
- import the selected backup artifact
- SQL release contract verification
- `booking:doctor --strict`
- `booking:deploy-check --mode=postflight --strict`

## Launch-readiness evidence

Limited production requires recent restore evidence, not just a backup file. Use the JSON from `booking:dr-drill` or a reviewed manual evidence record with these safe-to-share fields:

- `restored_dump_identifier`
- `restore_target`
- `verification_command`
- `verification_result`
- `performed_at_utc`
- `operator`
- `reviewer`

Do not include database passwords, provider credentials, connection strings, tokens, or dump contents in the launch-readiness manual evidence file. Automated tests should use dry-run/sample fixtures and must not execute destructive restore commands.

## CI/manual rehearsal

For a repeatable shell entrypoint, use:

```bash
scripts/ci/booking-restore-rehearsal.sh
```

This writes evidence to:

- `build/booking-ci/booking-restore-rehearsal.json`

This script remains a minimal restore rehearsal entrypoint. The canonical evidence workflow is now `booking:dr-drill`.

## Failure handling

- If the tool reports artifact hash mismatch, do not continue. Generate a new backup.
- If the target database is non-empty, prefer `--drop-target-first` for rehearsals.
- If `booking:doctor` or `booking:deploy-check` fails after restore, treat the rehearsal as failed and investigate before release.

## Production policy

- `db_all.sql` in source control is **not** a substitute for environment backup.
- Every release candidate should have a fresh backup plus at least one recent restore rehearsal record.
- Full restore rehearsal commands must target an isolated scratch database whose name makes the restore scope obvious.
