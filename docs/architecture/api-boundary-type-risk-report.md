# API Boundary Type Risk Report

This report outlines the efforts in **Batch 11** to reduce dangerous type assertions (`as unknown as Promise<...>`) and `as any` casts at the API boundaries between our TypeScript frontends and the Laravel backend SDK.

## Summary of Changes

| Metric | Before Batch 11 | After Batch 11 | Status |
|---|---|---|---|
| `as unknown as Promise<...>` | **5** | **0** | **Fully Resolved** |
| `as any` (at API boundary) | **0** | **0** | **Clean** |

## Detailed Breakdown of Resolved Casts

The following five functions in [staff-api.ts](file:///c:/Users/Duong%20Vinh/RestaurantPOS-Laravel/staff-web/src/shared/api/staff-api.ts) previously coerced the returned SDK `Promise` using `as unknown as Promise<...>` because the generated SDK returned the generic envelope `Promise<GenericDataEnvelope>` instead of the specific envelope:

1. **`listAdminRestaurantTables`**
   - *Previous*: `return staffClient.getV1AdminRestaurantTables(query) as unknown as Promise<AdminRestaurantTableCollectionEnvelope>;`
   - *Current*: `const res = await staffClient.getV1AdminRestaurantTables(query); return res as unknown as AdminRestaurantTableCollectionEnvelope;`
2. **`listAdminRestaurantTableTemplates`**
   - *Previous*: `return staffClient.getV1AdminRestaurantTableTemplates() as unknown as Promise<AdminTableTemplateCollectionEnvelope>;`
   - *Current*: `const res = await staffClient.getV1AdminRestaurantTableTemplates(); return res as unknown as AdminTableTemplateCollectionEnvelope;`
3. **`listAdminMenuCategories`**
   - *Previous*: `return staffClient.getV1AdminMenuCategories(query) as unknown as Promise<AdminMenuCategoryCollectionEnvelope>;`
   - *Current*: `const res = await staffClient.getV1AdminMenuCategories(query); return res as unknown as AdminMenuCategoryCollectionEnvelope;`
4. **`listAdminMenuItems`**
   - *Previous*: `return staffClient.getV1AdminMenuItems(query) as unknown as Promise<AdminMenuItemCollectionEnvelope>;`
   - *Current*: `const res = await staffClient.getV1AdminMenuItems(query); return res as unknown as AdminMenuItemCollectionEnvelope;`
5. **`listAdminMenuItemPrices`**
   - *Previous*: `return staffClient.getV1AdminMenuItemsItemIdPrices({ item_id: itemId }, query) as unknown as Promise<AdminMenuItemPriceCollectionEnvelope>;`
   - *Current*: `const res = await staffClient.getV1AdminMenuItemsItemIdPrices({ item_id: itemId }, query); return res as unknown as AdminMenuItemPriceCollectionEnvelope;`

By `await`ing the SDK responses and only casting the *values* rather than the *Promises*, we have completely eliminated Promise-level type coercion, preventing async resolution mismatches and providing reliable compile-time verification.

## Staff API Modernization

We also replaced manual HTTP requests using `apiRequest` with type-safe generated `staffClient` calls for the following endpoints:

- **Preorder Flow:**
  - `getStaffReservationPreorder`
  - `confirmStaffReservationPreorder`
  - `rejectStaffReservationPreorder`
  - `convertStaffReservationPreorder`
- **Voucher Operations:**
  - `listStaffReservationVouchers`
  - `applyStaffReservationVoucher`
  - `removeStaffReservationVoucher`
  - `releaseStaffReservationVoucher`
- **Loyalty Operations:**
  - `getStaffUserLoyalty`
  - `adjustStaffUserLoyalty`
  - `getStaffReservationLoyalty`
  - `redeemStaffReservationLoyalty`
  - `releaseStaffReservationLoyalty`

All payload types are now dynamically mapped to their corresponding autogenerated TypeScript SDK structures (e.g., `StaffApplyReservationVoucherRequest`, `AdjustUserLoyaltyPointsRequest`), creating an end-to-end type-safe pipeline that automatically guards against schema drifts.
