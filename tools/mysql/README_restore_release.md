# Restore release backup

This tool restores a previously generated backup bundle into a target MySQL database and then verifies the restored state.

## Requirements

- `mysql` CLI available on PATH or provided through `MYSQL_BIN`
- A backup manifest generated by `tools/mysql/backup_release.php`
- A scratch target database distinct from the source `DB_DATABASE` unless you intentionally pass `--allow-target-db-match`

## Basic usage

```bash
./tools/mysql/restore_release.sh --json
```

The tool resolves the latest backup manifest from `BOOKING_BACKUP_ROOT/latest-manifest.json` by default.

## Recommended rehearsal usage

```bash
export RESTORE_DB_DATABASE="${DB_DATABASE}_restore_rehearsal"
./tools/mysql/restore_release.sh --drop-target-first --json
```

For the canonical DR workflow and evidence artifact generation, prefer:

```bash
php artisan booking:dr-drill --mode=full-isolated-restore --target-db="${DB_DATABASE}_restore_drill" --drop-target-first --json
```

## Safety guards

By default the restore tool will fail when:

- `RESTORE_DB_DATABASE` is empty
- target database matches `DB_DATABASE`
- target database is non-empty
- backup artifact hash or byte count does not match its manifest

Use these flags only intentionally:

- `--drop-target-first`
- `--allow-nonempty-target`
- `--allow-target-db-match`

## Verification after restore

When available, the tool runs:

- `tools/mysql/verify_release_contract.sql`
- `php artisan booking:doctor --json --strict`
- `php artisan booking:deploy-check --mode=postflight --json --strict`

If the repository snapshot does not contain `artisan`, the Laravel verification phase is skipped and reported as a warning.
