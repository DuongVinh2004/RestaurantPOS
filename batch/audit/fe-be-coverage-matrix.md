## Status definitions

- `DONE`: UI + API + flow + basic tests are evidenced enough for static audit; live proof may still be separately required for release.
- `PARTIAL`: Some adapter/UI/flow/test exists but coverage is incomplete, gated, or missing runtime proof.
- `CONTRACT_ONLY`: Backend/generated contract exists, but no real FE flow was evidenced.
- `GATED`: FE or backend feature flag/rollout policy disables default exposure.
- `MISSING`: No relevant FE adapter/UI/flow evidence found in inspected files.
- `NOT_APPLICABLE`: Domain does not belong to that frontend.
- `UNKNOWN`: Insufficient static evidence; needs runtime or deeper source verification.

## Backend route inventory summary by group

The route-level CSV `docs/audit/fe-be-route-coverage.csv` contains the per-route rows with method/path/controller/middleware/capability/header/idempotency/row_version and FE coverage status. High-level route families:

- Auth / Identity / RBAC: customer and staff login/me/refresh/logout.
- Customer menu/catalog: categories, items, item detail, preorder preview.
- Table availability and holds: available table search, hold create/read/refresh/cancel.
- Reservation self-service: create/list/detail/cancel/reschedule.
- Customer preorder: reservation preorder show/preview/replace/clear plus `pre-order` aliases.
- Customer deposit and bill: deposit preview/intent/payment sessions; active-order/bill preview/bill/self-pay payment sessions.
- Waiting list: customer owner actions and staff manual queue actions/change feed.
- Staff operations: branch context, table board, reservation inbox/timeline/assignment/check-in/move, walk-in service sessions, ordering, line lifecycle, checkout, refund, cashier shift, finance review.
- Kitchen/KDS: station/ticket reads and dispatch/fire/bump/recall mutations.
- Admin/back-office: branch/table/zones/templates, menu, kitchen station config, inventory/procurement, benefits/loyalty, privacy, reporting snapshots, master-data import/export.
- Ops/release: public health, detailed health, Redis health, metrics, payment provider webhooks.

## Important static audit boundaries

- A page/component alone was not counted as `DONE`; the matrix checks for route/adapter/header/idempotency/row_version/state/test evidence where available.
- Generated SDK presence alone was not counted as `DONE`; it was counted as `CONTRACT_ONLY` or `PARTIAL` unless an actual frontend adapter/flow was evidenced.
- Payment-session and customer self-pay surfaces remain `PARTIAL` or `GATED` without real provider/runtime proof.
- Kitchen dispatch, inventory uplift, conversation inbox, customer waiting-list, account benefits, privacy tools, and data export remain gated/deferred according to inspected config/support matrix.
